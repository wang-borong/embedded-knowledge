\chapter{制造与可测试性设计}
\label{chap:manufacturing-dft}

可制造性设计（DFM）保证产品能够稳定装配，可测试性设计（DFT）保证缺陷能够被经济地检测和定位。它们必须在原理图和 PCB 阶段介入，而不是等试产失败后再增加飞线和人工步骤。

\section{生产测试目标}

生产测试主要发现来料、贴装、焊接、连接和配置缺陷，不应完整重复研发验证。测试覆盖应针对高概率、高影响且可检测的制造失效，例如开路、短路、错件、反向、虚焊、时钟异常和身份写入失败。

测试策略通常组合 AOI、X-ray、ICT、飞针、boundary scan、功能测试和最终整机测试。不同方法具有不同覆盖、节拍和工装成本。

\section{覆盖模型与缺陷逃逸}

生产测试覆盖的基本单位应是潜在缺陷及其可观测后果，而不是测试项数量。十个都只读取同一软件状态的测试，覆盖可能不如一次外部 loopback。项目应建立“缺陷---检测方法---工站---判定---逃逸风险”矩阵，至少覆盖：
\begin{itemize}
  \item 开路、短路、锡桥、偏移、反向和错件；
  \item 阻容值错误、器件批次或版本错误及关键参数漂移；
  \item 电源、时钟、复位、启动配置和存储装配异常；
  \item BGA/底部焊点、连接器、线束、天线和机械装配缺陷；
  \item 固件、区域配置、校准、设备身份和安全锁定位错误。
\end{itemize}

每个缺陷条目应说明现有方法是直接检测还是仅通过相关现象间接推断。例如功能测试能发现以太网不能通信，但未必能区分变压器焊接、PHY 时钟、MAC 配置或线缆工装问题；若定位成本高，应增加更早的结构化测量或诊断码。

覆盖矩阵还要记录假失败与漏测。一个限值过紧的测试可能拥有很高“失败检出率”却主要拦截良品；一个只验证芯片 ID 的测试可能非常稳定，却遗漏模拟通道装反。量产和 RMA 发现的逃逸缺陷必须回写矩阵，判断应修改设计、工艺、测试方法还是抽样策略。

硬件 revision、替代料、钢网、回流曲线、工装和测试软件变更都可能使既有覆盖失效。变更评审必须指出哪些缺陷模型仍成立、哪些测量需要重新做 GR\&R 或相关性验证，而不能默认沿用旧线体数据。

\section{测试点设计}

关键电源、地、复位、时钟、启动配置、调试接口和通信总线应提供可接触测试点。测试点需要考虑探针直径、间距、阻焊开窗、板边距离、治具压合方向和背面器件干涉。

高速差分线不应为方便测试随意增加长 stub。可使用小型焊盘、专用高频探点、连接器或在制造阶段通过芯片内部测试能力观测。

测试点命名应与原理图网络、PCB 和测试程序一致。自动导出测试点清单比手工维护坐标表更可靠。

图~\ref{fig:dft-analog-test-point} 展示模拟输入测试点的通用设计。工装通过保护电阻注入已知电压，板上分压和输入保护保持正常功能；测试程序同时检查输入增益、偏置和饱和边界。探针接触期间必须建立明确的模拟地参考。

\subsection{测试点电气契约}

测试点数据库不应只有 X/Y 坐标。建议同时导出网络名、板面、焊盘尺寸、允许探针类型、参考地、最大注入电压/电流、可接受负载、上电状态和禁止并发驱动条件。原理图、PCB、Gerber/ODB++、工装和测试程序应从同一受控标识建立映射。

对低阻电源、分流电阻和精密模拟节点，应考虑四线/Kelvin 测量，避免探针与走线压降进入结果。对高速或高阻节点，探针电容、stub、回流路径和仪器输入阻抗可能改变被测电路；若无法无扰动测量，应改用芯片内部监测、专用连接器或统计相关的替代观测，而不是隐藏测量影响。

工装接触顺序也属于接口契约。保护地或信号地通常应先接触、后断开；电源和激励只在压合到位、DUT 身份确认后使能。任何可能在 DUT 未上电时通过信号脚反向供电的通道，都应具有串联限流、隔离开关或明确禁止状态。

\subsection{定位、拼板与机械可达性}

定位孔、板边基准、fiducial、拼板连接和器件高度决定针床能否稳定重复接触。测试点不应位于易弯曲区、V-cut/铣槽邻近区域、过高器件阴影或受连接器插拔力影响的位置。板级设计规范可结合 IPC-2221 等通用 PCB 设计要求并由具体工厂、探针和治具能力细化\cite{ipc-2221}。

拼板测试需要把 panel ID、单板位置和最终序列号关联。若测试在分板前执行，应考虑公共电源/地、工艺边和相邻板耦合；分板后则需确认应力没有引入连接器、陶瓷电容或边缘走线损伤。机械基准变化必须触发工装坐标和压合分析更新。

\section{电源域与安全上电}

生产工装首次接触未知状态 PCB，应使用限流电源并分阶段上电。测试程序先检查输入短路和待机电流，再使能次级电源，避免把焊接短路扩大为器件烧毁。

每个电源域应具备电压测量点，关键轨可增加电流采样或可断开路径。PMIC 编程和 OTP 操作必须在电压、温度和前置测试通过后执行。

\section{工站状态机与安全联锁}

生产工站应使用显式状态机组织一次单板事务，例如：读取工单与工装自检、扫描 DUT、压合并确认地参考、限流预上电、验证电源轨、下载临时测试固件、执行结构/功能测试、写入校准与身份、执行不可逆锁定、安装正式镜像、最终复核、断电并释放。

每个状态都要定义允许进入条件、最大持续时间、失败后的安全动作以及是否可以重试。异常退出不能只终止上位机进程；还要关闭激励、电源与运动机构，释放身份预留并把 DUT 标记为待复核。若清理动作是否完成无法确认，该单板和工装槽位都应隔离。

夹具压合、保护门、气压、急停、过流、过温和高压测试应具有独立联锁。测试 PC 或网络服务不得是唯一保护层。工装控制器可以暴露有界命令，例如“上电到 profile 3”或“执行 ADC 激励步骤 12”，而不是允许远程任意设置所有继电器和电压。

每次工站事务应先生成唯一 run ID，并贯穿上位机、测试固件、身份服务和制造执行系统。即使中央网络暂时不可用，本地队列也要保证 run ID 与设备身份不重复；恢复上传应幂等，不能把一次测试复制成多个通过记录。

\section{调试与量产接口}

SWD/JTAG、UART、USB recovery 和 Boot ROM 下载接口应在研发、生产、维修和量产锁定之间形成生命周期策略。生产工装需要可靠接触，但最终产品不应向未授权人员暴露完整调试权限。

可以使用 pogo pin、Tag-Connect、边缘触点或专用连接器。接口布局应包含地参考和防反接定义，并避免测试探针接错时直接把外部电压送入 SoC 引脚。

\section{Boundary Scan}

IEEE~1149.x boundary scan 可以在不运行正常固件的情况下控制和观察兼容器件引脚，适合检测 BGA 之间难以接触的开短路\cite{ieee-1149-1}。板级设计需保证 JTAG chain、TRST、上拉/下拉和多器件 bypass 正确。

Boundary scan 只能观测链中器件与可控制网络，模拟节点、电源质量和非兼容器件仍需要其他测试手段。BSDL 文件、器件版本和链顺序应作为生产资产管理。

量产程序应在正式测试前读取 IDCODE、确认 chain 长度和器件顺序，再加载与精确器件封装/版本匹配的 BSDL。\texttt{SAMPLE/PRELOAD}、\texttt{EXTEST}、\texttt{BYPASS} 等指令具有不同驱动语义；在切换到可能驱动外部网络的指令前，应先装载安全向量，避免两个器件对同一网络争用。

跨电源域或可热插拔器件尤其需要确认未上电时的 JTAG 引脚容忍度、隔离和 back-power 路径。差分高速接口、AC 耦合网络、开漏总线和含存储状态的外设不能用普通静态开短路向量完全覆盖，需要 IEEE 1149.6 能力、外部回环或功能测试补充。

chain 过长会增加节拍和单点接触故障影响，可通过受控多路器或分链降低风险，但必须保证默认启动和现场调试路径确定。任何链拓扑变化都要同步 BSDL 集合、连接描述和 golden vector，不能仅更新 PCB 文件。

\section{ICT、飞针与功能测试}

ICT 适合高产量和稳定板型，可快速测量阻容、二极管和网络连通；飞针无需昂贵针床，适合样板和小批量，但节拍较慢。功能测试验证上电、时钟、存储、接口和传感器等整体行为。

功能测试应优先使用硬件唯一能力和 loopback，而不是只读取软件版本。例如 UART TX/RX 外部回环、Ethernet 包计数、ADC 已知电压和 GPIO 驱动/回读更能发现真实装配缺陷。

测试顺序通常先执行成本低、检出率高且不会损伤 DUT 的项目，再进入上电、下载、校准和长时间功能测试。AOI/条码/BOM 检查、短路筛查和低压预上电可以避免把明显缺陷带入昂贵工站；不可逆 OTP、证书签发和安全锁定应放在所有可恢复验证之后。

顺序优化不能删除故障隔离所需的观测。若两个测试高度相关，可以通过受控试产数据证明合并或抽样；不能只因节拍压力假定后一个“通常也会通过”。测试时间应分解为装卸、接触、自检、稳定等待、测量、写入和数据上传，针对真正瓶颈优化。

功能测试还应验证外部路径。例如麦克风由声源激励、扬声器由参考麦克风采集、相机使用受控靶标、射频使用屏蔽箱或耦合器。设备内部自报“发送成功”只证明软件路径，不证明连接器、匹配网络、天线或换能器已经工作。

\section{自测试固件}

生产测试固件应提供稳定、机器可读、可超时的命令接口。测试项必须独立返回状态、测量值、单位和错误原因。

\begin{lstlisting}[language=C,caption={生产测试结果的逻辑结构}]
struct production_test_result {
    uint16_t test_id;
    uint16_t status;
    uint32_t sequence;
    int32_t  measured_value;
    int32_t  lower_limit;
    int32_t  upper_limit;
    uint16_t unit;
    uint16_t detail_code;
    uint32_t duration_ms;
};
\end{lstlisting}

测试固件不应包含通用未认证内存读写、任意命令执行和私钥导出接口。量产结束后应切换到正式签名固件，并按生命周期策略关闭或限制测试入口。

命令协议应具有版本、长度、事务号、超时、取消和明确错误分类。上位机不得通过解析自由文本判断通过；固件也不应只返回布尔值，而应返回原始测量、单位、使用的内部通道/量程和稳定 detail code。测试程序负责应用受控限值，固件则保证测量语义稳定，二者版本必须在发布包中绑定。

测试固件应支持读取自身 build ID、目标硬件身份和能力列表，并拒绝未知板卡或不兼容工站命令。若生产测试需要临时关闭安全策略，必须由受控启动模式、短期授权或专用签名建立边界，完成后验证正式镜像、安全启动和调试锁定确已生效。

长操作应周期报告 progress，但 progress 不能替代最终结果。上位机超时取消后，固件必须进入已定义状态，避免后台仍在擦除 Flash、驱动执行器或等待下一条命令。工站重新连接时，应先查询当前事务和硬件状态，而不是假定 DUT 已复位。

\section{限值设计与测量系统}

生产限值应从设计规格、器件与工艺容差、环境范围和测量不确定度导出。良品样板的最小/最大值只能帮助估计过程分布，不能直接成为规格；否则尚未采到的真实边界会被误判，而共同的设计偏差也可能让所有样板一致地错误。

每个数值测试至少记录被测量、单位、仪器量程、分辨率、稳定等待、重复次数、原始值、补偿值、规格界限和生产判定界限。测量不确定度可按 JCGM GUM 方法组织\cite{jcgm100}。在高风险边界附近，可以使用 guard band 缩小直接通过区，并把灰区样本送入复测或工程评审；guard band 方向和宽度应由漏测/误杀风险确定。

工站相关性验证需要使用覆盖量程的稳定样本或参考源，而不只是同一块典型 golden board。新工站、换仪器、换探针、换算法或维修后，应比较偏差、重复性和再现性。若发现仪器超期或漂移，要评估从上次有效校准以来哪些批次可能受影响，不能只校准后继续生产。

离散判定也需要可测语义。例如“连接器正常”应说明检测了哪些 pin、接触电阻或 loopback 路径；“晶振正常”应说明频率、启动时间、幅度代理指标和温度条件。模糊的测试名称无法支持限值评审和现场逃逸分析。

\section{校准与身份写入}

校准需要可追溯标准源、测量不确定度和环境条件。校准参数应关联硬件序列号、板卡修订、工站、仪器和时间，并在写入后回读验证。

MAC、序列号、证书和安全计数器等唯一数据必须防止重复、跳号和错板写入。分配服务应采用事务：预留、写入、回读验证、提交；失败的预留记录需要可审计回收策略。

不可逆 OTP/eFuse 操作放在所有可恢复测试之后，并要求电源稳定、数据二次校验和显式授权。

\section{安全配置与设备身份}

设备身份流程应尽量避免私钥以明文经过通用工站 PC。优先在安全元件、TEE 或设备内部生成密钥，再把公钥或证书签名请求送到受控服务；若必须注入密钥，应使用 HSM、会话级包裹、最小权限和不落盘缓冲，并验证日志、core dump 和调试接口不会泄漏秘密。

制造身份应绑定至少以下事实：产品/板卡型号、硬件序列号、芯片或安全元件唯一标识、公钥/证书、MAC 等网络标识、正式镜像摘要、校准版本、工站 run ID 和生命周期状态。绑定记录必须由分配服务确认提交后才允许单板通过，避免“证书已签发但写错板”或“板已写入但后台未记账”。

OTP/eFuse 写入应采用计划---回读---授权---烧写---再次回读的两阶段流程。烧写计划列出每一位当前值、目标值、是否可逆和依赖条件；工具拒绝任何未在计划中的额外变化。安全启动 key hash、调试锁和防回滚计数器等高影响字段宜要求双人或阈值授权，并保存非敏感审计摘要。

返修换板、换安全器件和报废必须定义身份处置。旧证书是否撤销、序列号是否继承、校准是否重做、云端资产如何迁移，都不能由现场操作员临时决定。失败或报废设备上的未使用身份预留也要有可审计状态，禁止静默回收到另一台产品。

生产网络应与办公网和互联网访问隔离，工站只访问必需的镜像、身份、时间和结果服务。离线生产模式需要预分配的有界授权包、过期时间和防重复机制；恢复联网后按事务同步，不能依赖人工合并 CSV。

\section{工装机械与寿命}

针床、插座、连接器和定位柱都具有寿命。插拔力不应由板对板连接器或 PCB 单独承担，工装应限制压合行程并保证受力均匀。

测试工装需要周期自检、参考板验证和耗材更换计数。接触电阻逐步增大会表现为偶发通信或电压异常，不能一律判定为 DUT 失败。

工装设计应允许快速识别损耗件并安全维修：探针板、线束、插座、继电器、保险丝和参考负载具有独立料号与寿命计数。维护后不仅要确认工装“能运行”，还要使用 loopback、参考源和已知缺陷样本验证测量精度与检出能力。

参考板应锁定硬件、镜像和校准，并与普通在制品物理隔离。参考板随时间也会磨损或漂移，应定期与第二参考或实验室仪器交叉验证。若所有工站同时依赖同一错误参考板，它会形成共同原因，制造出一致但错误的数据。

压合力、行程和平行度应可检查；软件不应通过不断增加重试来补偿机械接触退化。某测试项的首次失败率随探针次数上升，通常是工装维护信号。耗材更换阈值可由接触电阻趋势、重试率和供应商额定寿命共同决定。

\section{数据与追溯}

生产记录至少包含 PCB/PCBA 版本、软件版本、测试规范版本、工站、工装、操作员或自动化身份、测量值和最终判定。只保存 Pass/Fail 会丢失过程趋势和早期预警能力。

测试限值应来自设计容差和测量不确定度。修改限值必须版本化，禁止为提高直通率直接放宽而不进行工程评审。

制造谱系应尽可能关联 panel/单板位置、PCB 批次、关键器件 lot/date code、替代料、钢网与回流线、装配时间、返修、测试 run、校准、身份和最终包装。追踪粒度应由故障隔离与供应链风险决定；并非所有普通阻容都需要逐件序列号，但安全、寿命或高逃逸风险物料应能定位受影响范围。

测试数据需要 schema、单位和缺失值语义。固件升级后字段名称相同但算法改变时，必须增加版本或生成新测量 ID，避免把不可比较数据画在同一控制图上。原始高频波形可以按策略归档摘要与异常样本，但最终数值、限值、校准和证据摘要不能只存在于工站本地。

数据访问应最小化并保护设备身份与生产秘密。日志不得包含私钥、完整授权令牌或可批量伪造设备的材料。删除和保留策略要同时满足质量追溯、客户隐私、合同和安全事件调查需要。

\section{重测、返修与隔离}

量产不能使用“重复测试直到通过”作为默认策略。首次失败必须保留，重测只能在预定义条件下发生，例如确认探针接触异常、工装自检恢复或完成受控返修。新结果应关联原 run ID、失败原因、采取的动作和批准人，最终状态区分首次通过、重测通过、返修通过和报废。

测试程序应把产品失败、工装/仪器失败、通信基础设施失败和操作错误分开。若一批板在多个无关项目同时失败，先检查公共电源、地、工装和软件版本；若单个测试项在多个工站漂移，则检查器件批次、工艺和限值。错误分类不应由操作员自由输入不可统计文本，而应使用稳定 reason code 并允许补充备注。

返修后至少重跑受影响网络、邻近工艺风险和最终放行集合。更换晶振可能需要重测时钟、射频和 EMC 代理指标；更换电源器件可能影响纹波、温升和校准。返修指导必须限制允许次数和方法，过度热循环或重复拆装会引入新的潜在缺陷。

连续出现相同缺陷、身份冲突、异常 OTP 状态或无法解释的间歇失败时，应隔离批次而不只是单板。隔离范围依据 panel、物料 lot、线体、工站和时间窗口逐步收敛，并保护样本供 X-ray、切片、电气分析或供应商联合调查。

\section{试产与量产导入}

试产阶段应统计缺陷 Pareto、测试覆盖、假失败、返修成功率和节拍。高频缺陷应优先反馈到设计、器件、钢网、贴装和测试方法，而不是持续依赖人工返修。

量产发布包包括制造文件、BOM、替代料、测试点、测试程序、限值、校准、工装文件和操作指导，并保证所有资产引用同一硬件版本。

\section{线体放行与变更控制}

新线体或停线维护后的放行应执行工装自检、参考源相关性、已知良品和已知缺陷样本、身份服务事务以及正式镜像校验。只用良品确认会验证“能够通过”，却不能证明关键缺陷仍会被拒绝。首件和末件结果可以帮助发现班次内漂移，但不能替代连续过程监控。

节拍验收应报告分布而不只报平均值，并区分人工装卸、设备等待、稳定时间、测量、编程和后台服务。并行工位可以提高吞吐，但共享电源、仪器、网络或身份服务会形成容量和共同故障点；峰值并发时仍需保证限值、时间戳和事务唯一性。

生产软件、限值或工装更新应先在隔离线/影子模式比较新旧结果，再由受控审批切换。版本回退也需要兼容已有校准、身份和数据 schema。紧急临时偏差必须记录适用批次、风险、补偿检查和到期时间，不能成为长期隐藏配置。

量产缺陷和现场 RMA 应形成同一 FRACAS 闭环。若现场缺陷理论上可由生产测试发现，应回查当时原始测量、限值、工装状态和测试覆盖；若无法发现，则更新 DFT 或增加过程控制，而不是仅在 RMA 流程中筛选。

\section{检查清单}

\begin{itemize}
  \item 是否以制造缺陷及逃逸风险建立覆盖矩阵，而不是只统计测试项数量？
  \item 高风险网络和电源是否具有可接触、可解释的测试点？
  \item 测试点数据库是否包含电气限制、地参考、接触顺序和机械可达性？
  \item 首次上电是否限流并按电源域分阶段验证？
  \item 工站状态机、异常清理和独立安全联锁是否经过故障演练？
  \item 调试、生产和维修接口是否具有生命周期权限？
  \item 测试固件是否机器可读、有界且不暴露危险通用接口？
  \item 生产限值是否来自规格、容差和测量不确定度，而非单块 golden board？
  \item 校准、身份写入和不可逆操作是否事务化并可追溯？
  \item 私钥、OTP 和调试锁是否由最小权限、回读和明确授权保护？
  \item 工装接触、定位、寿命、校准和自检是否管理？
  \item 生产数据是否保存测量值、限值、版本和基础设施状态？
  \item 重测、返修、隔离和报废是否保留首次失败及完整谱系？
  \item 线体变更是否用良品、已知缺陷和相关性数据完成放行？
\end{itemize}

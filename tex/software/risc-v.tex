RISC-V 起源于加州大学伯克利分校，目前由 RISC-V International 维护开放标准。
其基础 ISA 与标准扩展采用模块化设计，规范可公开实现；具体处理器核、SoC IP、扩展和软件仍可能具有各自的许可证或专利约束。
本节以公开的非特权与特权架构规范为依据\cite{riscvspec,riscvpri}，只介绍常用子集，
不应把这里的列表视为对当前全部标准扩展的枚举。

\subsection{Privileged Architecture}

RISC-V 特权架构定义了系统级的功能，包括异常处理、内存管理、中断处理等。

\subsubsection{特权级别}

特权架构定义 M、S、U 三类基本模式，其中 M-mode 是特权架构实现必须具备的模式，
S-mode 和 U-mode 是否存在取决于实现与目标平台：

\begin{enumerate}
  \item \textbf{用户模式（User Mode，U-Mode）}
    \begin{itemize}
      \item 最低特权级别
      \item 运行用户应用程序
      \item 受限的指令和资源访问
    \end{itemize}

  \item \textbf{监管者模式（Supervisor Mode，S-Mode）}
    \begin{itemize}
      \item 运行操作系统内核
      \item 管理虚拟内存
      \item 处理系统调用和异常
    \end{itemize}

  \item \textbf{机器模式（Machine Mode，M-Mode）}
    \begin{itemize}
      \item 最高特权级别
      \item 运行固件和引导代码
      \item 最低级别的硬件访问
    \end{itemize}

  \item \textbf{Hypervisor 扩展（H Extension）}
    \begin{itemize}
      \item 它不是位于 S-mode 与 M-mode 之间的独立“H-mode”
      \item 扩展后的 S-mode 作为 HS-mode 运行宿主 Hypervisor
      \item 客户机使用虚拟化的 VS-mode/VU-mode，并可使用两阶段地址转换
    \end{itemize}
\end{enumerate}

\subsubsection{控制状态寄存器（CSR）}

RISC-V 使用控制状态寄存器来管理系统状态：

\paragraph{机器模式 CSR}

\begin{itemize}
  \item \textbf{mstatus}：机器状态寄存器
  \item \textbf{misa}：机器 ISA 寄存器
  \item \textbf{medeleg}：机器异常委托寄存器
  \item \textbf{mideleg}：机器中断委托寄存器
  \item \textbf{mie}：机器中断使能寄存器
  \item \textbf{mtvec}：机器陷阱向量基址寄存器
  \item \textbf{mepc}：机器异常程序计数器
  \item \textbf{mcause}：机器异常原因寄存器
  \item \textbf{mtval}：机器陷阱值寄存器
  \item \textbf{mip}：机器中断挂起寄存器
\end{itemize}

\paragraph{监管者模式 CSR}

\begin{itemize}
  \item \textbf{sstatus}：监管者状态寄存器
  \item \textbf{sie}：监管者中断使能寄存器
  \item \textbf{stvec}：监管者陷阱向量基址寄存器
  \item \textbf{sepc}：监管者异常程序计数器
  \item \textbf{scause}：监管者异常原因寄存器
  \item \textbf{stval}：监管者陷阱值寄存器
  \item \textbf{sip}：监管者中断挂起寄存器
  \item \textbf{satp}：监管者地址转换和保护寄存器
\end{itemize}

\subsubsection{异常和中断}

\paragraph{异常类型}

RISC-V 定义了多种异常类型：
\begin{itemize}
  \item 指令地址未对齐
  \item 指令访问错误
  \item 非法指令
  \item 断点
  \item 加载地址未对齐
  \item 加载访问错误
  \item 存储/原子操作地址未对齐
  \item 存储/原子操作访问错误
  \item 用户模式环境调用
  \item 监管者模式环境调用
  \item 机器模式环境调用
  \item 指令页错误
  \item 加载页错误
  \item 存储/原子操作页错误
\end{itemize}

异常编号及可选异常会随扩展变化，例如 Hypervisor 扩展还定义客户机页错误；
软件必须依据目标规范版本和已实现扩展解释 \texttt{mcause/scause}。

\paragraph{中断类型}

RISC-V 支持多种中断：
\begin{itemize}
  \item 软件中断（Software Interrupt）
  \item 定时器中断（Timer Interrupt）
  \item 外部中断（External Interrupt）
\end{itemize}

\subsubsection{内存管理}

\paragraph{Sv32（32 位虚拟内存）}

\begin{itemize}
  \item 32 位虚拟地址空间
  \item 4 KB 页大小
  \item 两级页表
\end{itemize}

\paragraph{Sv39（39 位虚拟内存）}

\begin{itemize}
  \item 39 位虚拟地址空间（512 GB）
  \item 4 KB 页大小
  \item 三级页表
  \item 64 位系统常用
\end{itemize}

\paragraph{Sv48（48 位虚拟内存）}

\begin{itemize}
  \item 48 位虚拟地址空间（256 TB）
  \item 4 KB 页大小
  \item 四级页表
  \item 大型系统使用
\end{itemize}

\paragraph{Sv57（57 位虚拟内存）}

\begin{itemize}
  \item 57 位规范虚拟地址
  \item 4 KB 基础页大小
  \item 五级页表
  \item 是否实现由平台与处理器决定
\end{itemize}

\paragraph{页表项（PTE）}

RISC-V 页表项格式：
\begin{itemize}
  \item V（Valid）：有效位
  \item R（Read）：读权限
  \item W（Write）：写权限
  \item X（Execute）：执行权限
  \item U（User）：用户模式可访问
  \item G（Global）：全局映射
  \item A（Accessed）：已访问
  \item D（Dirty）：已修改
  \item RSW：保留给软件使用
  \item PPN：物理页号
\end{itemize}

\subsection{Unprivileged ISA}

RISC-V 非特权 ISA 定义了用户程序可以使用的指令。

\subsubsection{基本指令集}

\paragraph{RV32I（32 位基础指令集）}

\begin{itemize}
  \item 32 个通用寄存器（x0--x31）
  \item x0 硬连线为 0
  \item 基本整数运算指令
  \item 加载/存储指令
  \item 分支和跳转指令
  \item 系统调用指令（ECALL）
\end{itemize}

\paragraph{RV64I（64 位基础指令集）}

\begin{itemize}
  \item 扩展 RV32I 到 64 位
  \item 64 位寄存器
  \item XLEN 为 64，通用寄存器宽度为 64 位
  \item 实际实现的物理与虚拟地址位数可以小于 64 位
  \item 提供面向 32 位字运算的 \texttt{*W} 指令
\end{itemize}

\subsubsection{标准扩展}

\paragraph{M 扩展（乘法/除法）}

\begin{itemize}
  \item MUL：乘法
  \item MULH：高位乘法
  \item DIV：有符号除法
  \item DIVU：无符号除法
  \item REM：有符号取余
  \item REMU：无符号取余
\end{itemize}

\paragraph{A 扩展（原子操作）}

\begin{itemize}
  \item LR（Load Reserved）：保留加载
  \item SC（Store Conditional）：条件存储
  \item AMO（Atomic Memory Operation）：原子内存操作
  \item 用于实现锁和同步原语
\end{itemize}

\subsubsection{指令集组合与平台契约}

RISC-V 软件不能只检查“RV64”便假定扩展齐全。基础整数 ISA、乘除法、原子、压缩、浮点、向量和位操作等扩展分别版本化。编译器的 \texttt{-march}、链接对象的属性、Bootloader 暴露的 ISA 字符串和操作系统运行时探测必须一致。

平台还定义 ISA 之外的启动核、内存映射、中断控制器、定时器、固件接口和设备发现。SBI 是 S-mode 软件请求 M-mode 固件服务的标准边界，但实现哪些扩展、调用是否可阻塞以及错误码语义仍需依据目标版本\cite{riscv-sbi}。

\subsubsection{Trap 入口与返回}

Trap 入口的最小工作包括保存被覆盖寄存器、区分异常与中断、读取 cause/tval/epc、选择处理栈并建立可由高级语言使用的上下文。硬件不会像 Cortex-M 那样自动压入完整通用寄存器帧。

\texttt{mtvec/stvec} 可以使用 Direct 或 Vectored 模式。Vectored 模式只对中断按 cause 偏移，异常仍进入基址；入口地址还必须满足模式要求的对齐。处理程序返回前应确认：
\begin{itemize}
  \item \texttt{mepc/sepc} 指向重试指令还是下一条指令；
  \item 中断源已按平台顺序 claim、清除或 complete；
  \item 状态寄存器中的前一特权级和中断使能位正确；
  \item 嵌套 Trap 不会覆盖当前栈帧或 per-hart scratch。
\end{itemize}

ECALL、断点、非法指令和页错误需要不同的 PC 推进策略。尤其不能固定把 EPC 加 4，因为压缩指令可能为 16 bit，而可恢复的 fault 通常需要修正页表或状态后重试原指令。

\subsubsection{hart 本地状态与启动}

每个 hart 都有独立 CSR 和执行状态。多核启动时应为每个 hart 建立独立栈、Trap scratch、页表切换状态和 per-CPU 数据，再参与全局初始化屏障。主 hart 负责全局资源并不意味着其他 hart 可以在共享状态未发布时提前访问。

发布启动状态需要语言原子操作或与平台匹配的 acquire/release 同步。只把共享标志声明为 \texttt{volatile} 不能提供跨 hart 顺序。

\subsubsection{中断控制器与定时器}

特权规范只定义软件、定时器和外部中断的架构入口。具体平台可能使用传统 CLINT/PLIC，也可能实现 Advanced Interrupt Architecture（AIA）的 ACLINT、APLIC 和 IMSIC。驱动必须由 Device Tree、ACPI 或平台规范发现，不能把 QEMU \texttt{virt} 地址当作所有 SoC 的架构常量。

PLIC 的典型流程是读取 claim 获得中断 ID，处理设备源，再向 complete 写回同一 ID。优先级阈值、每个 context 的 enable 位和设备级清中断顺序共同决定是否重复触发。MSI/IMSIC 路径则把中断表示为面向 hart 的消息，适合虚拟化和 PCIe 设备。

时间服务应明确 \texttt{time} CSR、平台计时器频率和 SBI timer 的关系。频率来自固件描述而非 CPU 主频；跨 hart 比较时间戳前还要确认平台提供的同步保证。

\subsubsection{PMP 与物理隔离}

PMP 在 M-mode 配置物理地址范围和 R/W/X 权限，用于约束 S/U-mode。区域可以使用 TOR、NA4 或 NAPOT 等匹配形式，数量、粒度和是否实现由处理器决定。

配置时必须检查排序和锁定位：TOR 区域的下界来自前一 entry；锁定 entry 后通常要到复位才能修改，并可能影响 M-mode 访问。默认拒绝策略需要为固件调用缓冲、共享内存和设备 MMIO 建立最小窗口。

PMP 只限制 hart 发起的访问。DMA、调试模块和其他总线主设备仍需 IOMMU 或 SoC 防火墙。安全启动、PMP 和设备访问控制必须构成同一启动策略。

\subsubsection{虚拟内存与 TLB 一致性}

写入 \texttt{satp} 选择根页表和地址空间标识，但页表更新与地址转换缓存之间需要 \texttt{SFENCE.VMA} 协调。多 hart 系统修改另一个 hart 可能使用的映射时，通常需要：发布页表写入、向目标 hart 发送 shootdown、目标执行 \texttt{SFENCE.VMA}、确认完成后再回收旧页或物理内存。

大页要求虚拟地址、物理地址和 PPN 对齐；PTE 的非法 R/W 组合、A/D 位处理和访问权限必须遵循目标特权规范。页表 walker 是否与数据缓存一致、IOMMU 是否使用另一套页表，则属于具体 SoC 契约。

\subsubsection{RVWMO、FENCE 与原子顺序}

RISC-V 默认采用弱内存顺序模型 RVWMO。两个 hart 对普通内存的观察顺序不能从单线程程序顺序直接推出。同步应优先使用 C/C++/Rust 原子和锁，让工具链依据目标 ISA 生成 acquire、release、AMO、LR/SC 或 fence。

\texttt{FENCE} 的 predecessor/successor 集合区分设备输入、设备输出、内存读和内存写；\texttt{FENCE.I} 用于保证当前 hart 后续取指看到先前写入的指令内容。跨 hart 代码更新还需要使其他 hart 执行相应取指同步，不能只在写代码的 hart 调用一次。

MMIO 顺序还依赖平台内存属性与 interconnect。语言原子不能自动把设备寄存器变成普通缓存一致内存，驱动应使用操作系统或平台提供的 MMIO accessor 和 DMA API。

\subsubsection{向量扩展}

V 扩展采用向量长度无关模型。\texttt{VLEN} 是实现属性，程序通过 \texttt{vsetvl/vsetvli} 根据剩余元素和元素宽度选择本轮 VL，而不能假设固定 128 或 256 bit。

向量上下文包含大量状态，操作系统需要依据扩展状态位执行惰性或主动保存。中断/信号处理、任务迁移和虚拟机切换都必须保持 vtype、vl、vstart 和向量寄存器语义。算法验收应覆盖不同 VLEN 的模拟器或硬件，避免只在单一实现上正确。

\subsubsection{调试与性能监控}

RISC-V Debug Specification 定义 Debug Module、hart halt/resume、abstract command 和 program buffer 等机制。具体 SoC 还需要调试传输模块、复位和认证策略。量产状态不应默认保留可任意读写内存的调试权限。

性能计数器通过 \texttt{cycle}、\texttt{instret} 和实现定义事件提供证据，但事件含义、计数权限和多路复用方式必须记录。比较不同处理器时，应使用相同工作负载、编译参数、频率和缓存状态，而不是只比较 cycle 数。

\subsubsection{RISC-V 系统检查清单}

\begin{itemize}
  \item ISA 扩展字符串、ABI、工具链和运行时探测是否一致？
  \item Trap 入口是否覆盖压缩指令、嵌套、per-hart 栈和不可恢复故障？
  \item PLIC/AIA、timer 和 SBI 是否依据平台描述而非固定地址实现？
  \item PMP、DMA 防火墙、调试和安全启动是否形成完整隔离边界？
  \item 页表更新、TLB shootdown、代码更新和弱内存序是否使用正确同步？
  \item 向量和性能计数器代码是否在不同实现属性下验证？
\end{itemize}

\paragraph{F 扩展（单精度浮点）}

\begin{itemize}
  \item 32 位浮点运算
  \item 32 个浮点寄存器（f0--f31）
  \item IEEE 754 标准
\end{itemize}

\paragraph{D 扩展（双精度浮点）}

\begin{itemize}
  \item 64 位浮点运算
  \item 扩展 F 扩展
\end{itemize}

\paragraph{C 扩展（压缩指令）}

\begin{itemize}
  \item 16 位指令编码
  \item 减少代码大小
  \item 提高代码密度
\end{itemize}

现代通用软件平台通常还依赖 \texttt{Zicsr}、\texttt{Zifencei} 等扩展；
位操作（B）、向量（V）、加密及众多 \texttt{Z*} 扩展需要根据目标平台配置文件单独确认。

\subsubsection{寄存器约定}

\paragraph{通用寄存器用途}

\begin{itemize}
  \item x0：零寄存器（硬连线为 0）
  \item x1（ra）：返回地址
  \item x2（sp）：栈指针
  \item x3（gp）：全局指针
  \item x4（tp）：线程指针
  \item x5--x7（t0--t2）：临时寄存器
  \item x8（s0/fp）：保存寄存器/帧指针
  \item x9（s1）：保存寄存器
  \item x10--x11（a0--a1）：函数参数/返回值
  \item x12--x17（a2--a7）：函数参数
  \item x18--x27（s2--s11）：保存寄存器
  \item x28--x31（t3--t6）：临时寄存器
\end{itemize}

\subsubsection{调用约定}

\paragraph{参数传递}

\begin{itemize}
  \item 前 8 个整数参数通过 a0--a7 传递
  \item 在硬浮点 ABI 中，前 8 个浮点参数通过 fa0--fa7（f10--f17）传递
  \item 更多参数通过栈传递
\end{itemize}

\paragraph{返回值}

\begin{itemize}
  \item 整数返回值通过 a0 传递
  \item 在硬浮点 ABI 中，浮点返回值通过 fa0--fa1（f10--f11）传递
  \item 大结构体通过内存传递
\end{itemize}

\paragraph{调用者保存 vs 被调用者保存}

\begin{itemize}
  \item 临时寄存器（t0--t6）：调用者保存
  \item 保存寄存器（s0--s11）：被调用者保存
  \item 参数寄存器（a0--a7）：调用者保存
\end{itemize}

\section{内存层级}

现代计算机系统采用多级内存层次结构，以平衡性能、容量和成本。

\subsection{内存层次结构}

\subsubsection{层次结构}

典型的内存层次结构（从快到慢，从小到大）：

\begin{enumerate}
  \item \textbf{寄存器}
    \begin{itemize}
      \item 最快，容量最小（几十到几百字节）
      \item 位于处理器核心内部；相关指令的结果延迟通常至少为一个流水线周期，并非“0 周期”
    \end{itemize}

  \item \textbf{L1 缓存}
    \begin{itemize}
      \item 很快，容量小（32--64 KB）
      \item 通常位于核心内部；命中延迟依具体微架构而定
    \end{itemize}

  \item \textbf{L2 缓存}
    \begin{itemize}
      \item 较快，容量中等（256 KB--1 MB）
      \item 通常位于芯片内部，可为私有或共享缓存；延迟依具体实现而定
    \end{itemize}

  \item \textbf{L3 缓存}
    \begin{itemize}
      \item 中等速度，容量较大（几 MB 到几十 MB）
      \item 常见于高性能多核处理器，但许多嵌入式 SoC 不实现 L3
    \end{itemize}

  \item \textbf{主内存（DRAM）}
    \begin{itemize}
      \item 较慢，容量大（几 GB 到几 TB）
      \item 延迟受到内存类型、频率、控制器、排队和 NUMA 拓扑影响
    \end{itemize}

  \item \textbf{辅助存储（SSD/HDD）}
    \begin{itemize}
      \item 最慢，容量最大（几百 GB 到几十 TB）
      \item 访问延迟：数万到数百万周期
    \end{itemize}
\end{enumerate}

\subsubsection{访问时间对比}

\begin{table}[H]
  \centering

  \begin{tabular}{|l|l|l|}

  \end{tabular}
\end{table}

\subsection{缓存性能}

\subsubsection{缓存命中率}

缓存命中率是衡量缓存性能的重要指标：

\begin{equation}
\text{命中率} = \frac{\text{缓存命中次数}}{\text{总访问次数}} \label{eq:cache-hit-rate}
\end{equation}

\subsubsection{平均访问时间}

平均内存访问时间：

\begin{equation}
T_{avg} = T_{hit} + (1-H) \times T_{\text{miss penalty}} \label{eq:avg-access-time}
\end{equation}

其中：
\begin{itemize}
  \item $T_{hit}$：缓存命中时间
  \item $T_{\text{miss penalty}}$：未命中后相对于命中路径额外增加的代价
  \item $H$：缓存命中率
\end{itemize}

\subsubsection{缓存效率}

缓存效率取决于：
\begin{itemize}
  \item 命中率
  \item 缓存大小
  \item 替换策略
  \item 预取策略
\end{itemize}

\subsection{内存带宽}

\subsubsection{理论带宽}

内存的理论带宽：

\begin{equation}
\text{带宽} = \text{每次传输字节数} \times \text{每秒传输次数} \times \text{通道数} \label{eq:memory-bandwidth}
\end{equation}

DDR 存储器应使用有效数据传输率（MT/s），而不是简单使用时钟频率；
协议开销、读写切换、刷新、Bank 冲突和控制器效率会使持续带宽低于理论值。

\subsubsection{实际带宽}

实际带宽受多种因素影响：
\begin{itemize}
  \item 访问模式（顺序 vs 随机）
  \item 缓存效率
  \item 内存控制器效率
  \item 系统负载
\end{itemize}

\section{每个程序员都应该知道的内存知识}

内存是计算机系统中最关键的资源之一，理解内存的工作原理对于编写高效、正确的程序至关重要。本节总结程序员需要了解的关键内存知识。

\subsection{内存的基本概念}

\subsubsection{物理内存 vs 虚拟内存}

\begin{enumerate}
  \item \textbf{物理内存}
    \begin{itemize}
      \item 实际的硬件内存（DRAM）
      \item 有限的容量
      \item 直接由硬件访问
    \end{itemize}

  \item \textbf{虚拟内存}
    \begin{itemize}
      \item 程序看到的地址空间
      \item 可以比物理内存大
      \item 通过 MMU 映射到物理内存
    \end{itemize}
\end{enumerate}

\subsubsection{内存对齐}

\paragraph{对齐的重要性}

\begin{itemize}
  \item 未对齐的访问可能导致性能下降
  \item 某些架构不支持未对齐访问
  \item 对齐到自然边界可以提高性能
\end{itemize}

\paragraph{对齐规则}

\begin{itemize}
  \item 基本类型通常对齐到其大小
  \item 结构体对齐到最大成员的对齐要求
  \item 可以使用 \texttt{\_\_attribute\_\_((packed))} 取消对齐（不推荐）
\end{itemize}

\subsection{缓存友好的编程}

\subsubsection{数据访问模式}

\paragraph{顺序访问}

\begin{itemize}
  \item 顺序访问内存效率高
  \item 充分利用空间局部性
  \item 预取效果好
\end{itemize}

\paragraph{随机访问}

\begin{itemize}
  \item 随机访问效率低
  \item 缓存命中率低
  \item 应尽量避免
\end{itemize}

\subsubsection{数据结构设计}

\paragraph{紧凑的数据结构}

\begin{itemize}
  \item 减少内存占用
  \item 提高缓存利用率
  \item 减少缓存未命中
\end{itemize}

\paragraph{数据布局}

\begin{itemize}
  \item 将经常一起访问的数据放在一起
  \item 避免伪共享
  \item 考虑缓存行大小（通常 64 字节）
\end{itemize}

\subsubsection{循环优化}

\paragraph{循环顺序}

\begin{itemize}
  \item 按行访问优于按列访问（对于二维数组）
  \item 考虑内存布局（行主序 vs 列主序）
\end{itemize}

\paragraph{循环展开}

\begin{itemize}
  \item 减少循环开销
  \item 提高指令级并行
  \item 但可能增加代码大小
\end{itemize}

\subsection{多核编程的内存考虑}

\subsubsection{伪共享}

\paragraph{问题}

\begin{itemize}
  \item 不同线程访问同一缓存行的不同数据
  \item 导致不必要的缓存一致性开销
  \item 严重影响性能
\end{itemize}

\paragraph{解决方法}

\begin{itemize}
  \item 数据对齐到缓存行边界
  \item 使用填充（Padding）分离数据
  \item 将共享数据改为私有数据
\end{itemize}

\subsubsection{内存屏障}

\begin{itemize}
  \item 编译器屏障约束编译器重排，处理器内存屏障约束硬件可观察顺序，两者不能混为一谈
  \item 多线程程序优先使用语言和操作系统提供的原子操作、锁及内存序接口
  \item 屏障只在与缓存一致性、设备内存属性和通信协议正确配合时才保证预期行为
\end{itemize}

\subsection{内存分配}

\subsubsection{栈 vs 堆}

\begin{enumerate}
  \item \textbf{栈}
    \begin{itemize}
      \item 自动管理
      \item 速度快
      \item 容量有限
      \item 局部变量
    \end{itemize}

  \item \textbf{堆}
    \begin{itemize}
      \item 手动管理（或垃圾回收）
      \item 速度较慢
      \item 容量大
      \item 动态分配
    \end{itemize}
\end{enumerate}

\subsubsection{内存分配器}

\begin{itemize}
  \item 理解分配器的行为
  \item 避免频繁分配/释放
  \item 使用对象池减少分配
  \item 考虑内存碎片
\end{itemize}
